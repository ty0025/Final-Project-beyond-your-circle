## 4. Limitations (kept honestly)

- DNS rebinding: no check against the resolved IP; the risk is limited by a fixed hostname + TLS hostname verification. Not verified.
- The text of a malicious page is seen by the model (flag + spotlight + safety notice) but is not deleted; whether it is recommended depends on the model and the verifier, and this real run did not recommend it. If a real source page is tampered with, the card still shows that page's own link (from the collector, not from the page body or the model).
- URLs in the original page text are stored as plain text in the card data (not rendered as links); off-site URLs without a query string in model text are not deleted, they just do not become links.
- Rule screening only recognizes English wording; rephrased attacks depend on the LLM guard (model) judgment, and when the guard fails it lets the input through (fail-open), leaving only rule screening.
- A model call in progress at the moment of cancellation or timeout is not ledgered (cost is a lower bound); with `LLM_MAX_RETRIES=1`, after hitting the call cap there can be at most 1 more retry attempt.
- A system-prompt leak that contains no canary cannot be blocked by code.
- `style-src 'unsafe-inline'` is still kept.
- The real red-team sample is small (3 runs), synthetic pages, and valid only for gpt-6-luna/Portkey on 2026-10-25.
- Known issue G-11 in the Question 5 logic is still present (q06 §8).
