### 4.2 Capabilities the new domain needs that the current interface lacks (public collection not yet implemented)

1. Outbound HTTP collection: allowlist, timeouts, size and page-count limits, safe redirects; **must use a separate httpx client**, not reuse the model client that carries the key header.
2. Source registry: drives collection, the URL allowlist, and UI display.
3. Unified record schema: original URL, organizer, collection time, field-provenance original text, missing values. Note that under a strict schema `dict[str,str]` compiles to an empty object, so provenance fields must use a list structure.
4. America/New_York date windows (this week/next few weeks/long term), which need `tzdata`; the current date should come from tool output rather than the system prompt, so as not to break prompt caching.
5. Hard-condition filtering: unknown = to confirm.
6. Output schema: match reasons, participation conditions, items to confirm, data freshness.
7. Manual refresh and source status endpoints; cache/live/fixed snapshot labels.
8. Collected content entering the safety layer: web HTML falsely triggers the injection heuristics; `ALLOW_DOMAINS` strips query strings/long paths from real event links; new tools must explicitly set `untrusted_output=True`.
9. Test network guard: once a collector exists, offline tests must block real network access.
10. If collection/refresh calls a model, it must go through the same gateway, budget, and ledger (currently the budget only takes effect inside `run_task`).
