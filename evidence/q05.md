## 1. Four items handled separately (`app/domain/conditions.py`, `app/domain/verify.py`)

| Dimension | Decided by | Content |
|---|---|---|
| Topic relevance | Code | `relevance`: in which page field (title/topic/summary/conditions) the user's interest words and the model's search words appear |
| Specific participation purpose | Model (stored as "reasoning") | `reasoning.why`: how it serves the user's purpose; `reasoning.interaction`: the form of interaction the page describes, which **must have a verbatim quote**, otherwise it is replaced with "the page does not describe ... no guarantee of meeting specific people or speakers" |
| Hard participation conditions | Code, checked against what the user **said** | Format (online/in person), time window (this week / next few weeks, real America/New_York dates), audience restrictions ("undergraduates only", etc.), prerequisites, age, membership, participating vs. watching, registration status, capacity; each is `met` / `not_met` / `to_confirm` / `info`, with the original page text attached |
| Unknowns | Code | Fees, capacity, location, etc. that the page does not state go into `next_steps` and the fact table (`value: null, basis: "not stated on the page"`) |

**Status is decided by the server**; the model's `fit` cannot override it:
- Any hard condition `not_met` → removed from recommendations and moved to "Not a fit for you", with the reason;
- Any hard condition `to_confirm` → "Possible match: check first" (conditional recommendation);
- Otherwise → "Match";
- An exploratory pick must provide a `link_quote` that appears verbatim in the page, goes through the same hard-condition checks as a match, at most 2, and may be zero.

**Facts and reasoning are stored separately**: each recommendation's `facts[]` is restored by the server from the stored record (`field`, `value`, `page_wording`, `basis`, `source_url`, `collected_at`); `reasoning{}` stores only the model's text, labeled as authored by gpt-6-luna with quotes checked by code.

**Fields without a source are rejected**:
- When the model's text contains a price, clock time, date, weekday, link, email, or phone number that the page does not have, it is replaced with "[detail not on the page]" and recorded in `rejected_details`;
- The output schema is `extra="forbid"`, so the model cannot add fields;
- A record_id that does not exist, was not read, or can no longer be attended is always dropped with the reason stated (already in Question 4, kept in this question).

## 2. Output contract and prompt changes

- `UnderstoodRequest` gains a structured `time_window` (this_week / next_few_weeks / not_stated); it states that "attend regularly" is a purpose, not a time window (addressing the inference observed in Question 4).
- `Pick` becomes: `why`, `interaction`, `interaction_quote`, `exploration_link`, `link_quote`, `evidence_quotes`; `watch_out` is removed, and eligibility judgment is now done by the server.
- The prompt tells the model not to judge eligibility itself, not to write dates/prices/locations/links in its reasoning, not to promise meeting speakers or any type of people, and that exploratory picks must have a quotable connection.
- The Ask tab shows sections: status badge; "AI explanation (quotes checked by code)"; "Conditions checked by code against what you said" (✓ ✗ ? i); Next steps; cards; an expandable "Facts and where they come from (restored from the stored page, not from the AI)"; "Not a fit for you"; code verification summary.

**Follow-up review fixes (2026-10-26, later the same day).** A read-only review of the fix above (Claude Code, throwaway probes, no model call) confirmed issues 1–7 in the participation rules; none could wrongly mark a listing "Not a fit", but several restricted or negated wordings still came out `met`. 1. A short quote from another check ("in-person", "open to all", "members of …") no longer hides a restriction in the same sentence ("This in-person workshop is restricted to Yale affiliates." → format met + audience to confirm, card Check first).

4. Negated wording ("not open to the public", "not the general public") is never read as open.
5. Each eligibility text is searched on its own, so a quote never runs into the next text.
6. The catch-all ignores credits ("eligible for 1.5 CME credits"), sizes written in words and speaker affiliation, and still flags real access wording ("Yale affiliates only.", "Limited to Yale students.").
7. "Undergraduate" counts as a student identity, and Browse and Find use one shared "open to all" pattern, so they read the same audience wording the same way.
