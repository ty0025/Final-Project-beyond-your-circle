## 8. Known issues and limitations (not changed, awaiting decision or later questions)

1. Question 5 logic (frozen): when a page says "Open to Yale students / the Yale community", it is judged met even if the user has not stated an identity; eligibility text the rules do not recognize does not generate a "to confirm" condition (the frontend now shows the original text on the card).
2. The AI summary may disagree with the code counts (this time "three close matches" vs 1 Match + 2 Check first); this is labeled and the code counts take precedence; the model text was not rewritten.
3. Real worst-case wait is about 6 minutes (guard 2×90 s failure pass-through + matcher 2×90 s); the UI prompts that it can be stopped after 45 s; no overall time cap was added (belongs to Question 7).
4. When cancelled, the model call in progress is not recorded in the ledger; the UI states that the cost is a lower bound.
5. Old styles in screenshots (q03–q05) are kept as historical evidence.
