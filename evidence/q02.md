## 3. Safety and boundaries

- The collector uses a **separate** `httpx.Client(trust_env=False, follow_redirects=False)`: no API key, no Authorization, no environment proxy or `.netrc`, no cookies stored. The test `test_requests_carry_no_api_key_and_honour_crawl_delay` checks that no request header contains key/`authorization`/`portkey`.
- No private content is fetched: no login, no form submission, no YaleConnect member pages, no Slack/email.
- No paid search or extra API key was introduced (consistent with C-12 / I-04).
- Web content is treated only as data: in this question the parsers only do pattern matching and do not hand page text to a model; when handed to an agent later, it must go through `untrusted_output=True` and spotlighting (Question 1 §4.2 item 8).

## 4. Unified record and the "unknown" rule

- Each record keeps: `url` (original detail page), `publisher`, `organizer`, `collected_at` (UTC time the page was fetched), `timezone=America/New_York`, `date_text` (original date/term), `start`/`end` or `sessions[]`, `format`+`format_text`, `location_text`, `eligibility_texts`, `cost_text`, `registration_url`/`registration_text`, `capacity_text`, `summary`, `evidence[]` (field + original text + page location), `missing[]`, `warnings[]`.
- Not stated = `null` and listed in `missing`; **never inferred as free, unlimited capacity, or open to everyone**. A registration link is recorded only as a link and does not imply open spots; "Registration closed/Register" is stored as in the original.
- `kind`: a single dated event page = `event`; a course/practice series = `program`, with each session's date kept inside `sessions` and **not split into separate events**; sessions whose time says "flexible" get no date.

## 7. Failures and fallbacks (all **simulated** faults, `httpx.MockTransport`)

| Test | Proves |
|---|---|
| `test_network_failure_keeps_and_serves_last_success` | Simulated network loss: returns `cached`, original `collected_at`, same records; cache file bytes unchanged; status `failed` + `network` |
| `test_partial_failure_carries_previous_record_forward` | Simulated single-page 503: status `partial`, failed page reuses the previous record (with its original fetch time) |
| `test_empty_listing_does_not_erase_previous_records` | Empty listing: status `empty`, last successful records kept |
| `test_without_cache_falls_back_to_committed_snapshot_then_unavailable` | Without a local cache, the committed snapshot is used (`snapshot`, dated); with neither, `unavailable` + `failed` ("no data", not "no events") |
| `test_robots_txt_is_obeyed` (3 cases) | `Disallow: /` (e.g. events.yale.edu) → refused; 404 → allowed; 503 → refused |
| `test_redirect_off_the_allowlist_is_blocked_and_allowed_redirect_followed` | Redirect to a non-allowlisted host blocked; same-site relative redirect followed |
| `test_size_page_and_content_type_caps` | Oversize, non-HTML (PDF), and over-page-count all blocked |
| `test_only_https_allowlisted_urls_are_requested` | http, off-site, and username-bearing URLs send no request at all |

No network failure occurred in the real runs; the fallback capability is currently proven only by the simulated tests above (no real fault occurred).

- ycgs-events: first page of the event listing; takes URL dates from "today (America/New_York) to +75 days", at most 10 pages (currently 9). No pagination.
